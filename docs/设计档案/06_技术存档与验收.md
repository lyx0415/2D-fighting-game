# 技术、存档与验收

TypeScript5.9.3、Phaser3.90.0、Vite7.1.12，HTML/CSS负责页面HUD。Vitest3.2.4测独立规则，Playwright1.56.1测浏览器。Node24.18.0已使用，固定依赖与锁文件。

核心模拟不依赖渲染，1/60秒固定步，0.1秒AI决策，可注入随机种子。输入move/attackTarget/castSkill/switchHero，表现消费事件。静态HeroDefinition/EnemyDefinition/SkillDefinition/LevelDefinition，持久HeroProgress/EquipmentInstance/SaveData，临时Battle/BattleReward分离。详见../CONTENT.md及src/core/types.ts。

## 存档

正式键ashen-oath.v1，备份.backup。保存角色等级经验、可选talents/skillRanks分配、编队队长、装备归属、金币、解锁首通、已结算runId与设置；不保存战斗过程。主档损坏读取有效备份，两者都坏提示确认新档，不静默覆盖。写失败提示，仍保留内存进度。不同设备/域名/端口不共用存档。

调试键ashen-oath.v1.debug.new/squad/growth；开发环境有种子、范围、AI状态与跳波。生产必须无DEV入口与全局桥接。构建后实际开战验证当前位图资源，不能只看命令退出码。

## 验收

- 规则：移动追击、技能CD/无目标、投射物、伤害护盾、倒地全灭与双灭、波次唯一、结算幂等、招募、换装强化出售、概率、存档备份。
- 流程：新档点按完整十关、第三关前四人、第三关通关后五人、可换阵容重玩、不刷关可通。
- 浏览器：Chromium/Edge和WebKit；1280×720、1920×1080、844×390、915×412；触屏事件、UI不穿透、后台/失焦/竖屏暂停。
- 真机：Android Chrome、iPhone Safari仍需实际验证，记录设备与浏览器。
- 性能：桌面接近60FPS、中端手机30FPS是目标，未有专项测量；模拟耗时不等于帧率。

运行npm run dev（5173）；npm run build；npm run preview（4173）。Windows构建临时目录在.cache，开发监控排除测试输出与临时浏览器锁文件。生产构建、启动与当前缺口以最新交接为准。

## v0.2.0兼容与内容上限

LEVELS.length决定开放与校验上限；MAX_LEVEL来自经验表，当前10。version1的字段与物品ID保留。有效旧档在loadSave阶段调用unlockContinuation，只在当前前沿关卡已有通关记录时继续开放；旧版第三关已通则开放第四关，未通则仍第三关。不能用重置存档处理升级兼容。

新增chapter.spec.ts覆盖旧档续接、新场景、新Boss预警/结尾与生产新关卡。campaign.spec.ts通过ASHEN_FULL_CHAPTER=1选择完整十关鼠标流程；测试只读状态，移动施法/换装强化使用实际UI。结算可能发生于状态读取与技能点击之间，测试短超时后仅在战斗确已结束时忽略该次点击，其余失败仍报错。

## v0.3.0结构

LevelDefinition追加可选reinforcements，Battle管理后阵一次触发，既有存档字段不变；不持久化当场增援、技能缓冲和承伤统计。STAGE_WIDTH=2200，FLOOR=360～620供引擎及场景共用。

art.ts为兼容入口，hero-art.ts、chapter-map.ts、skill-icons.ts分别承担英雄、舆图和技能图形；TypeScript允许.ts扩展名导入，满足Node资产导出与Vite共同解析。资产导出不再动态求值整段源码。

新增回归覆盖增援不重复/未清后阵不能过关、普通敌人威胁、两档休整、路外拒绝、技能点按缓冲；浏览器验证连线节点/大Boss/触屏/新图形，并保持正式版无调试入口。Phaser独立打包，业务包约120KB，引擎约1.48MB（均未压缩），整体仍需真机性能验证。
